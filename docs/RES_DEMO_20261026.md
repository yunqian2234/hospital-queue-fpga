## 2. SW4：板上显示分辨率

- **SW4 拨上**：底行的“温馨提示 + 滚动字幕”换成当前图片的信息。
  - 左边青色“PIC2.BMP”是正在显示的是卡上哪个文件。
  - 后面是“原图 宽×高 → 显示 宽×高”。
  - 换图（轮播或按 KEY2）后立即跟着变。
- **SW4 拨下**：恢复滚动字幕，和以前完全一样。
- 调亮度、音量等的 3 秒提示，以及操作被拒绝的红字提示，仍然优先显示，3 秒后回到分辨率行。
- 照片还在加载时不显示（显示“照片加载中”）。

### 原理（答辩可以讲）

1. **原始宽高**：`bmp_stream_decode` 读文件头第 18~25 字节得到宽、高。尺寸超出 640×480 ~ 1920×1080 的文件直接拒绝（错误码 E01）。
2. **显示尺寸**：`bmp_scaler` 由宽高算出缩放比和缩放后的宽高。
3. **新模块 `SD/bmp_res_info.v`**：
   - 每张图加载成功时，把这四个数用“移位加三”法转成十进制；
   - 存进一块双时钟块 RAM 的第 N 项（N = 图片号）。
4. **大厅屏**按当前显示的图片号读出这一项，写在底行。

整条路径上没有任何人工写入的数字：评委给什么文件，屏上就出现那个文件头里的尺寸。

## 5. 答辩演示流程（约 2 分钟）

**准备**：笔记本、读卡器、TF 卡，SW4 拨上。

1. **先看 4 张轮播图**：底行依次出现 4 种不同的原图分辨率；16:9 的图上下有边，4:3 的铺满。
2. **评委出题**：
   - 请评委随便报一个宽和高（640~1920 × 480~1080），例如 1500×900。
   - 在笔记本上用 Windows 画图打开任意一张图，“重新调整大小”→“像素”，取消“保持纵横比”，填评委的数字，另存为“24 位位图”，名为 `PIC1.BMP`。
   - 右键 → 属性 → 详细信息，给评委看 Windows 读出的宽高。
3. **事先预测**：
   - 运行 `python tools/board_preview.py PIC1.BMP --ui`，屏幕上立刻打印“原图 1500×900 → 显示 640×384，上下各 48 行暖白留边”，还会生成预期画面。
   - 也可以当场在白板上算：缩放比 = min(640/宽, 480/高)。
4. **拷卡上板**：
   - 复位后，底行显示“PIC1.BMP　原图 1500×900”，和 Windows 属性一致；画面的比例和留边与预测图一致；
   - 画面的边和预测图一样。
5. **反例**：放 CAL09（2000×1000）。屏顶出现“图片错误 E01”，这张图不显示，其他图照常轮播。说明板子是真读了文件头，而不是看图上写的字。
6. **标定图**：放 CAL07（竖图），圆还是圆、四角颜色方向正确、外框完整。

> **一定要先预演**：用画图另存的 BMP 我检查过格式规则（24 位、无压缩、自下而上），应能读，但还没有在实板上试过。请你们答辩前用画图存几张，在板上走一遍上面的流程。

## 6. 预览工具

```
python delivery/res_demo_20261026/tools/board_preview.py <BMP 文件或文件夹> [--ui] [--pic N] [--out 目录]
```

- 先按板子的规则检查文件。不合格会打印原因，例如“尺寸 2000×1000 超出 …”“不是 24 位无压缩 BMP”。
