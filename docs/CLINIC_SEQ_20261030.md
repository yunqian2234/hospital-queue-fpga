# 10/30 诊室板：多需求卡依次展示、在途命令不串诊室

本轮只改**诊室板**，大厅板一行没动（大厅资源只剩约 0.4%，见 SPECTRUM_20261029.md）。

## 一、本轮做了什么（新增或修复）

### 1. 多需求卡依次展示（新增）

**原来**：患者报到时选了多个沟通需求（例如“听力差”加“需翻译”），诊室只放大**第一张**需求卡，其余的不出现。

**现在**：
- 同一位患者登记的需求卡全部依次展示：听力差、说话困难、头晕需搀扶、需家属或翻译，顺序固定。
- 每张卡都完整走一遍放大 → 停留约 5 秒 → 缩回，然后下一张卡放大。
- 放大框下方标题写明“X 诊室 NNN 号  需求 i/n”，例如“1 诊室 007 号  需求 1/2”，下一张是“需求 2/2”。
- 全部放完后回到正常页面。

**快照**：一张卡放大时，标题里的诊室、号码和 i/n 在发出这张卡时就固定下来，之后到达的叫号或状态更新不会改动正在展示的卡。

**各种情况的处理**（下面每一条在 `tb_need_seq.sv` 里都有对应场景）：

| 情况 | 处理 |
|---|---|
| 双诊室同时来了两位有需求的患者 | 先放 A 列的全部卡，再放 B 列的 |
| A 列正在放卡时，B 列来了新患者 | A 列全部放完，再放 B 列的 |
| 正在放某位患者的卡时，**同一诊室**叫了下一位 | 当前这张卡放完；旧患者剩下的卡不再放（他已不是该诊室的当前患者）；接着放新患者的卡 |
| 求助打断了一张需求卡 | 先放求助卡，再把被打断的那张卡**重放一次**并放完整，然后继续 |
| 同一张卡被打断两次 | 跳过这张卡，继续下一张，避免无限重复 |
| 同一位患者的登记重复到达 | 不重复放 |
| 卡放大中切换单/双诊室模式或诊室开关 | 当前这张放完（标题仍然冻结），剩下的卡和排队的患者都作废，不会把卡放到错误的诊室下 |
| 卡放大中断链 | 同上；重新连上后也不会补放旧卡 |
| 卡放大中复位 | 复位后，从当前患者的第 1 张卡重新开始放 |
| 没有需求、未登记、单诊室模式下的 B 列 | 不放卡 |

### 2. 在途命令不随模式切换改变诊室（修复）

**原来的问题**：医生按键后，命令会反复重发，直到大厅确认。如果这期间拨了“单/双诊室”开关或诊室开关，原代码会出两个问题：

- **命令发错诊室**：重发帧里的诊室号、读取确认的位置都跟着新诊室走，原本 2 诊室的“叫下一位”会被大厅当成 1 诊室执行。用旧代码跑新测试已复现，记录在 `evidence/cmd_room/old.log`："hall ran it for room 0 (want room index 1)"。
- **帧被截断**：双诊室切到单诊室时，B 路正在发送的以太网帧会被直接截断。

**现在**：
- 命令在途期间，它所属的诊室被冻结（`clinic_link.cmd_room`），重发帧和确认读取都用原诊室。命令完成后，新的按键才使用新诊室。
- B 路的发送开关只在帧与帧之间关闭，不会截断帧。若切换时 B 路还有在途命令，会继续重发直到被确认或超时，结果不会悄悄丢失。单诊室模式下 B 路按键照旧不接受。
