# 触摸屏（陶晶驰）报到登记页面制作说明 — 2026-10-25 耳鼻喉科版

本文写给负责触摸屏工程的同学。FPGA 一侧已按下面的命令做好；屏这边只需要改页面和按钮。

从零做整个屏工程的分步教程（控件表、全部按钮代码、下载和联调）见 [TOUCH_HMI_TUTORIAL_20261025.md](TOUCH_HMI_TUTORIAL_20261025.md)。

## 1. 命令格式（不变）

每个按钮在**弹起事件**里发一帧：

```
printh 5A <cmd> <arg> <chk> FF FF FF
```

- `chk = 5A ^ cmd ^ arg`（按字节异或）。
- `cmd`、`arg` 都必须小于 0x80。

## 2. 命令表

| 按钮 / 时机 | cmd | arg | 说明 |
|---|---|---|---|
| 进入登记页（页面的前初始化事件） | 08 | 00 | 清空上一位患者没提交的选择 |
| 沟通需求（可多选，见第 4 节） | 05 | 需求位 0x00–0x0F | bit0 听力差，请书写；bit1 说话困难；bit2 头晕需搀扶；bit3 需家属或手语翻译 |
| 主要症状（单选） | 06 | 00–09 | 00 听力下降、01 耳鸣、02 耳痛或流脓、03 鼻塞流涕、04 鼻出血、05 咽痛、06 声音嘶哑、07 吞咽困难或异物感、08 头晕、09 其他 |
| 难受程度（单选） | 07 | 00–0A | 0 到 10 级 |
| 报到（提交） | 03 | 00 | 原来的“取号”。FPGA 把前面的选择绑定到新号 |
| 请帮助我 | 01 | 00 | 不变 |
| 重播当前号 | 02 | 00 | 不变（可选） |
| 页面通知（不变） | 04 | 00/01/02 | 0 主页，1 报到页，2 求助页 |

补充说明：

- 每一项都可以不选，直接点“报到”。诊室屏会显示“未登记 / 未填写”。
- 同一项重复发送时，以最后一次为准。
- 原来的“请写下来 / 请再说一遍 / 是 / 不是 / 不是这个意思”5 个按钮请删除。FPGA 不再接受 `cmd 01` 加 `arg 1~5`。

## 3. 举例（帧可以直接复制）

| 操作 | 帧 |
|---|---|
| 进入登记页 | `printh 5A 08 00 52 FF FF FF` |
| 只勾“听力差” | `printh 5A 05 01 5E FF FF FF` |
| 勾“听力差 + 需翻译”（bit0 + bit3 = 0x09） | `printh 5A 05 09 56 FF FF FF` |
| 症状“耳鸣” | `printh 5A 06 01 5D FF FF FF` |
| 难受程度 6 | `printh 5A 07 06 5B FF FF FF` |
| 报到 | `printh 5A 03 00 59 FF FF FF` |
| 请帮助我 | `printh 5A 01 00 5B FF FF FF` |

## 4. 多选的做法（建议）

1. 页面上放一个数值变量 `need`，初值为 0。
2. 每个需求按钮做成双态按钮，按下时把 `need` 对应的位置 1 或清 0。例如“听力差”按钮：`need=need^1`。
3. 每次改完 `need` 后，用 `printh` 发 `5A 05 need chk FF FF FF`。校验在屏里算不方便的话，可以把 16 种组合的完整帧做成 16 条，用 `if` 选着发。

## 5. 页面建议

- 主页：大按钮“报到”和“请帮助我”。
- 报到页：
  - 上半部分：4 个需求按钮（双态、大字、带图标）。
  - 中间：10 个症状按钮（单选）。
  - 下面：0~10 的表情量表（11 个按钮或滑块）。
  - 最底部：一个大的“确认报到”按钮。
- 文本框 `t0`、`q0` 的名字不要改。FPGA 会往这两个框里写状态：
  - `t0` 示例：“报到成功：007号，前面还有3人”“2诊室已收到，马上到”。
  - `q0` 示例：“当前006号  下一位007号  候诊03人”。

## 6. 自测

FPGA 收到登记命令后不会回显，可以这样确认：

1. 报到后叫号。
2. 叫到这个号时，诊室屏对应诊室那一栏应显示刚才选的需求、症状和难受程度。
3. 如果选了“听力差”，大厅屏的叫号区还会闪烁黄色底。
