# 扩展要求3：不同分辨率图片自适应 HDMI 输出（方案A）· 2026-10-21

## 功能

- TF 卡上的 `PIC1.BMP`～`PIC4.BMP` 不再要求必须是 640×480。接受 **640×480 ～ 1920×1080**（官方要求不低于 640×480）的 24 位无压缩 BMP，任意宽高比。
- 大厅板读卡时边读边缩放到 HDMI 输出分辨率 640×480，**保持宽高比，多余部分用深蓝色 #1A2C4A 填边（居中）**（10/26 起填边色改为暖白 #FAFAF9，见 `RES_DEMO_20261026.md`）。例：1920×1080、1280×720 → 640×360，上下各留 60 行；1080×1080 → 480×480，左右各留 80 列；4:3 图片铺满全屏。
- 640×480 原图逐像素不变（与以前完全相同）。
- 缩放后图片照常进入帧缓存，**轮播、淡入淡出/擦除、缩略图、亮度/对比度、叫号界面、语音、诊室联动全部不变**。
- 尺寸不在范围内的图片（小于 640×480 或大于 1920×1080）不显示，报错误码 1（文件头不符），其余图片照常显示，与以前对坏图片的处理一致。

## 缩放算法（答辩要点）

“区域平均 + 双线性插值”，全部定点运算，流式处理，不需要整帧缓存：

1. 由 BMP 文件头读取原始宽高 W×H，求缩放比 s = min(640/W, 480/H)。
2. **区域平均预滤波**：k = ⌊1/s⌋（1～3），先把每 k×k 个原像素求平均。普通双线性只取相邻 2 个点，1920→640 这种 3 倍缩小会跳过三分之二的像素，细线、文字、密集条纹产生锯齿和摩尔纹；先平均相当于先低通滤波再采样。
3. **双线性插值**：区域平均后的中间图再按 16 位小数步长、像素中心对齐做水平和垂直线性插值（8 位权重），得到最终 Wo×Ho。
4. 实现：行缓存放在原来空闲的 32K 块 RAM（3 块），乘法用 DSP；R/G/B 三通道分时共用一条运算流水线。SD 卡 25 MHz SPI 约 96 个时钟才送来一个像素，分时不影响加载速度。

质量对比（1920×1080 → 640×360，以高质量 Lanczos 缩放为参考的 PSNR，越高越好）：

| 测试图 | 最近邻 | 普通双线性 | 区域平均+双线性（本设计） |
|---|---|---|---|
| 环形波带片（摩尔纹测试） | 10.5 dB | 10.5 dB | **23.1 dB** |
| 细线/条纹测试卡 | 13.5 dB | 13.5 dB | **16.2 dB** |

对比图见 `delivery/image_scale_20261021/evidence/image_scale_mutations/quality_*.png`（`*_crop_x2.png` 为三种方法同一局部放大并排）。

## 使用

1. **完全关闭 TD**，再打开大厅工程 `src/td_project/HDMI1.4b_Transmitter_v1.0.al` 编译。文件列表里应有新文件 `SD/bmp_scaler.v`，没有被排除（灰色）。工程里布局种子已设为 **8**（10/22 修复触摸卡顿后重新扫种子的结果，见 `delivery/touch_pause_20261022/README.md`；大厅板 slice 已用到 96%，时序对种子很敏感），**请不要改种子**；编译后时序报告应为 0 违例（建立 +0.048 ns、保持 +0.024 ns），不一致请截图发给助手。
2. TF 卡：可以继续用现在的四张 640×480 照片（效果与以前相同），也可以换成任意 640×480～1920×1080 的 24 位 BMP，文件名仍为 `PIC1.BMP`～`PIC4.BMP`。演示用的四张不同分辨率医院海报在 `delivery/image_scale_20261021/tf_demo_scale/`（1920×1080 / 1024×768 / 1280×720 / 800×600，各带 `_board_preview.png` 预览板上效果）。只替换这四个文件，AUDIO.PCM、VOICE.PCM 不动。
3. 诊室板、触摸屏不需要更新。

**加载时间**：读卡速度不变，加载时间与文件大小成正比。1920×1080 的 BMP 约 6.2 MB，是 640×480（0.9 MB）的 6.75 倍，开机后四张都加载完会比以前慢，第一张显示出来之前多等几秒属正常。
